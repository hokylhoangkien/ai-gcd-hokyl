# GPU training handoff

## What this repository solves

The GCD component consumes **product crops**, not full shelf images. A detector
or planogram crop generator must run first. For each crop the model predicts a
known SKU or assigns it to a novel SKU cluster. Full planogram compliance
(expected facings, shelf position, gaps, and adjacency) is a downstream module
and is not silently conflated with category discovery.

```text
Shelf image -> detector/cropper -> Retail GCD -> SKU/novel cluster
            -> planogram matching/compliance engine
```

## Required GPU environment

- Linux or Windows with an NVIDIA GPU.
- Python 3.10 or 3.11 recommended.
- A CUDA-compatible PyTorch build.
- At least 16 GB VRAM for ViT-B/16 with batch size 32; otherwise reduce the
  batch size and use gradient accumulation when added.

Create the environment:

```bash
python -m venv .venv
source .venv/bin/activate          # Linux
# .venv\Scripts\activate          # Windows PowerShell
pip install torch torchvision --index-url https://download.pytorch.org/whl/cu128
pip install -e .
python -m pytest -q
```

The CUDA index must be changed to match the installed driver. Confirm with:

```bash
python -c "import torch; print(torch.__version__, torch.cuda.is_available(), torch.cuda.get_device_name(0))"
```

Do not start a long run if `torch.cuda.is_available()` is `False`.

## Data contract

Place product crops under `data/processed/planogram_crops`. Create
`data/processed/planogram_manifest.csv` using the schema in
`data/manifest.example.csv`.

Rules:

- `labeled`: known SKU crops whose labels may enter supervised losses.
- `unlabeled`: disjoint crops containing both known and novel SKUs.
- `val`: labels are used for checkpoint selection and tuning only.
- `test`: labels are used once for offline final evaluation, never during training
  or checkpoint selection. `validate_config` rejects `test` in
  `data.validation_splits`.
- A novel SKU must never appear in `labeled`.
- Keep crops from one source image/video burst/session in only one data split.
- Remove duplicate and near-duplicate images across splits.
- OCR confidence must come from OCR or a documented calibration method.
- Barcode, database SKU ID, and complete catalog names must be removed in the
  leakage-controlled protocol.

Validate:

```bash
retail-gcd-validate data/processed/planogram_manifest.csv \
  --image-root data/processed/planogram_crops
```

## Mandatory pilot sequence

Run these methods with the same split, backbone, seed, and class count:

1. `simgcd_style`
2. `selex_adapted`
3. `get_adapted`
4. `debgcd_adapted`
5. `simple_fusion`
6. `proposed`
7. `oracle` using manually verified attributes only, as a separate upper bound

Use the configs generated by `scripts/generate_experiments.py` and a different
`output_dir` for every run. Run at least seeds 1, 2, and 3. Never overwrite
outputs across seeds. Adapted baselines are not official reproductions; see
`UPSTREAM_AUDIT.md` for exact differences.

## Main command

```bash
retail-gcd --config configs/planogram_proposed.json
```

Generate all primary ablation configs:

```bash
python scripts/generate_experiments.py --seeds 1 2 3
```

Resume by setting the root `resume` field to the previous `last.pt`. Each run
writes:

- `resolved_config.json`
- `class_mapping.json`
- `metrics.json`
- `last.pt`
- `best.pt` selected by Known/Novel harmonic mean on the configured validation
  split (default: `val`), never on `test`

Evaluate independently of training:

```bash
retail-gcd-eval --checkpoint outputs/planogram_proposed/best.pt --splits test
```

For estimated-K, export training features then search a predeclared range:

```bash
retail-gcd-extract --checkpoint outputs/planogram_proposed/best.pt \
  --splits labeled unlabeled --output outputs/planogram_features.npz
retail-gcd-estimate-k --features outputs/planogram_features.npz \
  --min-classes 100 --max-classes 300 --step 5
```

Choose the K search interval before viewing test labels. The implemented
estimator combines labeled-set clustering agreement with an intrinsic cosine
silhouette score and is reported as a heuristic, not an oracle.

## Preflight run

Before the full job, temporarily set:

```json
"epochs": 1,
"max_train_batches": 2,
"max_eval_batches": 2
```

Check that losses are finite, CUDA memory is stable, the checkpoint is written,
and both known and novel samples occur in evaluation. Remove both batch limits
for real results.

## What must be reported

- All, Old/Known, New/Novel and harmonic accuracy.
- NMI and ARI.
- Mean and standard deviation over at least three seeds.
- Natural-OCR and leakage-controlled OCR protocols.
- Sibling-SKU subset results.
- OCR corruption and missing-attribute robustness.
- Head/medium/tail class results.
- Oracle and estimated novel-class-count settings as separate experiments.

## Current limitations

- The current training path uses oracle total class count from the manifest.
- Estimated class count is implemented as an offline feature-based heuristic;
  training a new classifier with the estimated output dimension still requires
  placing that chosen value into the experimental protocol.
- No public dataset is bundled. Use RetailVision/planogram SKU crops for the
  primary result; see `DATASET_AND_TRAINING_GUIDE.md`.
- No result on private RetailVision/planogram data exists yet.
- Full planogram geometric compliance is outside this GCD package.

These limitations must not be hidden in a paper or demo.
